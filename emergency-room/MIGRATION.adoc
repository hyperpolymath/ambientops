== Build and Run

[source,bash]
----
# From ambientops/ root
cargo build -p emergency-room
cargo test  -p emergency-room

# Trigger mode (same as emergency-button)
./target/debug/emergency-room trigger
./target/debug/emergency-room trigger --dry-run

# Boot loop detection
./target/debug/emergency-room boot-guardian --record
./target/debug/emergency-room boot-guardian --check

# Graceful shutdown orchestration
./target/debug/emergency-room shutdown-marshal --reason user-initiated
./target/debug/emergency-room shutdown-marshal --dry-run

# Memory pressure / oomd observer (read-only, no process killing)
./target/debug/emergency-room pulse --once
./target/debug/emergency-room pulse --poll-seconds 20

# Install as user service
./emergency-room/systemd/install-pulse.sh
----

== Feature Parity

All V features are preserved:

* `trigger` subcommand — incident bundle, diagnostics, receipt, backup, handoff
* `boot-guardian` — boot stamp file, loop detection (5 boots / 10 min window),
  PCIe link-error scan from dmesg (CC-003)
* `shutdown-marshal` — component notification (observatory/clinician/session-sentinel
  via systemctl or SIGTERM), ungraceful-shutdown tracking, clean shutdown record
* `pulse` (`oom-watch` alias) — journal-based `systemd-oomd` kill detection and memory-pressure
  notifications with dedupe/cooldown and persistent cursor state
* PII redaction, path validation (CRIT-001/CRIT-002), atomic writes
