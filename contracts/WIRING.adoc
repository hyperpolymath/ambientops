== Contract Schema Wiring

How AmbientOps contract schemas connect producers to consumers.

=== Wired Schemas

[width="100%",cols="21%,30%,30%,19%",options="header",]
|===
|Schema |Producer(s) |Consumer(s) |Status
|`+evidence-envelope+` |emergency-room (`+--envelope+`),
hardware-crash-team (`+scan --envelope+`) |observatory
(`+ingest-envelope+`), records/referrals (`+submit_from_envelope+`)
|*Wired*

|`+procedure-plan+` |hardware-crash-team (`+plan+`) |clinician (apply),
composer (orchestrate) |*Wired*

|`+receipt+` |emergency-room (`+write_receipt+`), hardware-crash-team
(`+apply --receipt+`) |observatory (`+ingest+`) |*Wired*

|`+system-weather+` |observatory (`+weather+`) |nafa-app (satellite:
`+GET /api/weather+`) |*Wired*
|===

|===

                          ┌─ hardware-crash-team
emergency-room ──envelope──┤                          ┌─ observatory ──weather──→ (nafa-app satellite)

                               │                      │
                            plan/apply ──receipt──────┘
                               │
                          records/referrals ◄──envelope── (submit findings)
....

=== Validation

All schemas are validated by `+contracts/+` (Deno + JSON Schema) and
`+contracts-rust/+` (serde types).

[source,bash]
----
cd contracts && deno test   # Schema validation tests
cargo test -p contracts     # Rust type round-trip tests
----
